# signatures/ 接口清单（各模块负责人提交）

每个模块对外接口的清单放这里。**由各模块负责人自己整理提交**，不用等别人：

- 3 论文辅导：丙
- 4 论文检测：甲、乙
- 7 导师反馈追踪：丁

一个模块一个文件（如 `signatures/inspect.md`、`signatures/track.md`、`signatures/coach.md`）。接口的"提供方"主写清单（工具名、参数、返回），"消费方"补充确认。

## 模板（每个接口一份，照抄填）

```markdown
## <接口名>（如 inspect.query_latest）

- **提供方**：<模块名>（<负责人>）
- **消费方**：<模块名>（<负责人>）
- **用途**：<一句话，它解决什么问题>
- **形态**：MCP 工具（OPEN-3 定案）
- **参数**：
  - `参数名`：<类型>，<必填？>，<含义>
- **返回**：<结构说明；字段多时引用 DOC-003 对应小节的契约>
- **错误**：<错误码及含义（如 ERR_INVALID_REQUEST）>
- **优先级**：P0 / P1
- **交付周**：<第 X 周>
- **四件套**：fixtures □ / 断言 □ / 桩 □
```

## 约定

- 先冻结清单，再写代码；改动走契约评审（DOC-004 §3.1）。
- 清单与 `contracts/tests/<接口名>/`、`contracts/fixtures/<接口名>/`、`tools/devkit/stubs/<接口名>.py` 一一对应。
- 清单里只列"对外接口"；4 内部甲↔乙的交接（文档结构、问题候选）不在这里，写在 DOC-003 §4.2.3。
