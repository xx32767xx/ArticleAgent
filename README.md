# 论文智能辅导平台（347 部分）· 科搭 Codar 插件开发

> 我们组负责「科技论文智能辅导平台」需求文档里**图片结构总览的 3、4、7 三项**，做成科搭 Codar 平台的插件来交付：
> - **3 论文辅导智能体**：教你怎么写，但不替你写——丙负责
> - **4 论文检测智能体**：查问题、说清楚问题在哪、能复检——甲、乙负责
> - **7 导师反馈落实追踪**：把导师意见变成待办、跟进落实、留好记录——丁负责

## 快速开始

**环境**：在 conda 环境里装依赖（根目录统一维护，改动请走 PR）：

```powershell
pip install -r requirements.txt
```

**新同学或新会话，按这个顺序读：**

1. `docs/交接说明.md`（DOC-001）——入口、进度、现在卡在哪（**先读这个**）
2. `docs/决策记录.md`（DOC-002）——已经定下来的决策、还没定的问题
3. `docs/协作规范.md`（DOC-004）——目录怎么分、个人空间、分支和合并规则（**开工前必读**）
4. `docs/347模块接口与交互规范-v0.2.md`（DOC-003）——接口怎么设计
5. `docs/平台调研-Codar插件体系.md`（DOC-005）——科搭平台是什么、插件怎么组成

## 协作约定

- **个人空间** `members/<代号>/`：每个人自己的开发空间和个人文档，会进仓库（方便备份和互看），但不是交付物，公共代码不依赖它。
- **公共区域**：接口定义（`contracts/`）的改动要先和搭档确认；决策记录只往后追加；接口变了更新接口规范。
- **合并规则**：个人空间的改动自己合并（可以开自动合并，检查通过就进 main）；公共区域的改动要一个人看过再合。详见 `docs/协作规范.md`。
- **临时文件**放 `temp/`；我们只做本地提交，推送和远程仓库由负责人负责。
