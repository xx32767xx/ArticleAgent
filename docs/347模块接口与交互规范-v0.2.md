# 347 模块接口与交互规范 v0.2

> **文档编号：DOC-003** · 状态：评审中
> 范围：3 论文辅导智能体（讲解型辅导）、4 论文检测智能体（检测型辅导）、7 导师反馈落实追踪
> 依据：需求说明书 V1.1（M4 / M5 / M9 章节）、Codar 插件体系调研（`_codar_plugin_dev_notes.md`）
> 版本变化：v0.2 落地**职责隔离设计**——模块间以**接口调用**交互（7 为记录与追踪服务、4 提供评价查询），文件契约作为接口的底层实现与降级形态。
> 状态：设计初稿，待评审（⚠ 标记处为待确认项）

## 0. 目的

在 **Codar 插件（Skill）形态**下，3/4/7 是三个互相独立的能力单元。为了保证三者之间以及与编辑器（M3）、平台留痕（M9）之间的交互可测试、可留痕、可复用，本规范约定：

1. 各模块的**职责边界**与**禁止事项**（职责隔离）；
2. 模块之间的**接口契约**（调用方向、输入/输出 JSON）；
3. 交互**时序**与**状态机**；
4. 所有过程记录的**留痕事件契约**；
5. 契约在 Codar 中的**落地形态**（MCP 工具 / scripts CLI，文件契约兜底）。

## 1. 架构位置与职责隔离

### 1.1 职责隔离原则（本次设计核心）

| 模块 | 职责（只做这个） | 提供接口 | 消费接口 | 禁止事项 |
|---|---|---|---|---|
| **3 论文辅导** | 指导论文生成：讲解、骨架、追问、范例、自检清单 | 无（被 Agent 调用） | ① **4 的评价查询接口**（辅导时获取当前评价）② **7 的记录接口**（每次辅导上报） | ❌ 不做论文评价、不生成问题清单；❌ 不写留痕存储（交给 7） |
| **4 论文检测** | 对论文做评价：规则检测、问题清单、评分、复检 | ① **评价查询接口**（供 3 消费）② **7 的记录接口**（每次检测上报） | 7 的记录接口（检测批次与问题状态） | ❌ 不做讲解/指导；❌ 不写留痕存储（交给 7） |
| **7 追踪** | 记录与追踪服务：过程记录（唯一写入方）、待办/状态机、复核、统计 | ① **记录接口**（record.*）② **查询接口**（board/events/verify） | 无（只被调用） | ❌ 不做评价、不做讲解；❌ 不直接改学生正文 |

调用方向（依赖单向，无环）：

```
学生 ──> M3 编辑器（不在本规范范围）
          │
          ├──> [3 辅导 Skill] ──评价查询──> [4 检测 Skill]
          │         │                        │
          │         └────record.*───┐       └────record.*───┐
          │                        ▼                       ▼
          │                  [7 追踪服务：唯一记录写入方、状态机、复核]
          │                        │
          └──学生落实修改──────────>│（查询看板/待办）
                                   ▼
                            导师复核（M5 动作，经 7 记录）
```

- **过程记录统一走 7**：3/4 不各自落库，保证"谁记录、谁负责"唯一，天然满足 M9「只增不改」。
- 3 获取的评价结果**只用于辅导**（选择讲解侧重、关联问题、学习路径推荐），不得转存为评价结论。
- 4 输出的评价**只作为问题清单/评分**，不得代写或提供改写稿。

### 1.2 与需求文档的对应

- 3 ↔ M4 讲解型辅导（8.4 FR-M4-01/02/03/08、14.2）；4 ↔ M4 检测型辅导（8.4 FR-M4-04~07、14.3、14.4）；7 ↔ M5 落实闭环（9.2~9.5、AC-06/AC-09）+ M9 留痕（13.2「AI 辅导对话」「检测—整改闭环」「导师评语与评审」）。
- 单模块闭环（图 4-2）：讲解(3)→初稿→检测(4)→导师评语→落实(7)→复检(4)。

## 2. 通用约定

### 2.1 身份
- `project_id`：论文项目（一篇论文一个项目）；`module_id`：对齐 8.2/8.3，如 `abstract`、`introduction`、`methods`、`experiments`、`conclusion`、`references`。
- `session_id` / `run_id` / `issue_id` / `event_id`：`uuid4`，本地持久化后不变。
- `doc_version`：编辑器版本号（字符串，递增）；检测结果必须绑定版本。

### 2.2 编码与时间
- UTF-8 JSON；字段 camelCase；时间 RFC 3339 UTC。
- 严重度：`P0`（阻断）/`P1`（建议）/`P2`（提示）。
- 错误对象：`{ "error": { "code": "...", "message": "..." } }`。

### 2.3 接口形态（Codar 落地优先级）
1. **MCP 工具**（推荐）：7 为直连 MCP server（stdio 本地运行，Python 标准库实现，零依赖）；4 的评价查询可随 4 的 Skill 提供同一 MCP 的另一组工具，或同样以 CLI 暴露。
2. **scripts CLI**（降级/备选）：`track.py` 子命令、`inspect.py query` 子命令；无 MCP 环境下由 Agent 直接执行命令并读取输出。
3. **文件契约**（底层实现，不做接口约定）：所有落盘格式仍按本规范 §4/§7 的 JSON 定义，供 MCP/CLI 与测试断言复用。

服务根目录（相对项目工作区）：
```
<project-workspace>/
  coach/sessions/<session_id>/{request.json, report.json}
  coach/checks/<run_id>/{request.json, report.json}
  advisor/{board.json, actions.jsonl}
  evidence/events.jsonl          # 由 7 写入（哈希链）
```

## 4. 模块与接口定义

### 4.1 3 论文辅导智能体（讲解型辅导）

**触发**：学生首次进入模块（BR-01 先讲解后写作）、主动求教、追问；或检测后推荐学习路径（FR-M4-08）。

**辅导时的调用流程（职责隔离关键）**：
1. 调 **4 的评价查询接口**（§4.2.2）获取当前模块最新评价（若有）；
2. 依据评价结果决定辅导侧重：高频问题类别 → 六段式"常见错误"侧重、关联具体问题、给出学习路径（FR-M4-08：如"你反复出现引用格式错误，建议看第 6 讲 8 分钟片段"）；
3. 生成 `CoachReport`；
4. 调 **7 的记录接口 `track.record_session`**（§4.3.2）上报本次辅导。

**输入 `CoachRequest`**：
```json
{
  "schemaVersion": "coach.request.v1",
  "task": "explain|followup|path",
  "context": { "...": "§3 的 Context 对象" },
  "question": "摘要写多少字合适？",
  "priorSessionId": null
}
```

**输出 `CoachReport`**（固定六段式，对齐 14.2；新增评价联动字段）：
```json
{
  "schemaVersion": "coach.report.v1",
  "sessionId": "uuid",
  "task": "explain",
  "contextUsed": { "latestCheckId": "uuid|null", "issueIds": ["uuid"], "issueCategories": ["A", "D"] },
  "sixSections": {
    "what": "是什么（≤150字+1个类比）",
    "howMuch": "写多少（篇幅/段数/字数配比区间）",
    "howTo": ["步骤1", "步骤2", "步骤3"],
    "mistakes": [{"example": "错误示例", "why": "为什么错", "fix": "怎么改"}],
    "contrast": {"good": "优秀片段(匿名)", "bad": "待改进片段", "notes": "点评"},
    "selfCheck": ["可勾选项1", "可勾选项2"]
  },
  "skeleton": { "paragraphs": 3, "perParagraph": ["写什么1", "写什么2"], "suggestChars": "250-500" },
  "followupQuestions": ["追问1", "追问2", "追问3"],
  "sentenceTemplates": ["句式模板1", "句式模板2"],
  "sources": [{ "ref": "讲义第3讲", "anchor": "摘要四要素", "time": "8:30" }],
  "linkedIssues": [{ "issueId": "uuid", "topic": "摘要缺结论要素", "advice": "重点讲结论如何与结果呼应" }],
  "learningPath": ["讲义第3讲 8:00-12:00", "练习：写出结论句"],
  "guardrail": { "generatedChars": 0, "note": "只给结构与句式，未产出可整段粘贴的成稿" }
}
```

**约束（红线，14.1）**：
- G-01：输出中**可直接使用的连续正文 ≤ 60 字**，超限降级为"提纲+问题+句式位"。
- G-02：学生未提交本模块初稿时，`contrast` 不给全文/完整段落改写。
- G-05：学生"不会写"类提问，先给 1–2 个追问或结构提示，连续两次求助才升级强提示。
- 评价联动不得改写评价原文为"可直接粘贴的成稿"；`linkedIssues` 仅引用，不复述全文。

### 4.2 4 论文检测智能体（检测型辅导）

**触发**：初稿提交（check）、段落体检（paragraph）、修改后复检（recheck，增量）、全量检测（full）。

#### 4.2.1 检测接口（主流程）

输入 `CheckRequest`：
```json
{
  "schemaVersion": "check.request.v1",
  "scope": "module|paragraph|full",
  "context": { "...": "§3 的 Context 对象" },
  "targetText": "……（scope 决定范围）",
  "prevReportId": "uuid|null",
  "ruleSetVersion": "2026.11"
}
```

输出 `CheckReport`（对齐 14.3 + 16 章 Issue 实体）：
```json
{
  "schemaVersion": "check.report.v1",
  "runId": "uuid",
  "scope": "module",
  "docVersion": "v12",
  "durationMs": 3200,
  "rulesetVersion": "2026.11",
  "summary": { "P0": 2, "P1": 5, "P2": 3, "total": 10 },
  "moduleScore": { "structure": 4, "content": 3, "logic": 4, "language": 4, "standard": 3, "pass": false },
  "issues": [{
    "issueId": "uuid",
    "category": "A|B|C|D|E|F",
    "ruleId": "CK-STR-01",
    "anchor": { "section": "摘要", "paragraph": 2, "charStart": 40, "charEnd": 120 },
    "snippet": "原文片段（≤25词）",
    "severity": "P1",
    "basis": "判定依据",
    "teachingExplanation": "为什么这是问题",
    "suggestions": ["修改建议1"],
    "knowledgeRef": "讲义第3讲#摘要结论缺失",
    "status": "open",
    "prevIssueId": "uuid|null"
  }]
}
```

**问题生命周期**：`open → accepted|fixed|appealed → closed`（复检确认）/`reopened`（复发）；C-01 句级定位、C-02 增量 ≤8s/全量 ≤90s、C-04 可解释、C-06 复检三段式。
**对 ModuleState 的影响（BR-03）**：P0 存在 → `待修复`；P0 全关闭 → 可申请 `通过`（导师确认）。
**检测完成后**：调 **7 的记录接口 `track.record_check`**（§4.3.2）上报批次与问题。

#### 4.2.2 评价查询接口（供 3 调用）

```json
// inspect.query_latest(projectId, moduleId) -> CheckSummary | null
{
  "schemaVersion": "inspect.summary.v1",
  "runId": "uuid",
  "docVersion": "v12",
  "checkedAt": "2026-11-16T08:00:00Z",
  "summary": { "P0": 2, "P1": 5, "P2": 3 },
  "topIssueCategories": ["A", "D"],
  "topIssues": [{ "issueId": "uuid", "category": "A", "title": "摘要缺结论要素",
                  "severity": "P0", "anchor": { "section": "摘要", "paragraph": 2 } }],
  "moduleScore": { "structure": 4, "content": 3, "logic": 4, "language": 4, "standard": 3 }
}
```
- 只返回摘要级信息（最多 top 5 issues），不返回完整建议正文，避免 3 直接复制评价内容；
- 3 需要细粒度信息时（如按类别取全部问题），可调 `inspect.query_issues(projectId, moduleId, {severity?, category?, status?})`（⚠ 是否开放由评审决定）。

### 4.3 7 导师反馈落实追踪（追踪与记录服务）

**定位**：7 是**过程记录的唯一写入方**与**追踪服务提供方**。3/4 不各自落盘，统一把"做了什么"上报给 7；7 负责哈希链事件流、待办状态机、复核与统计。

**职责边界**：❌ 不做评价（不产生 Issue）❌ 不做讲解（不产生讲解内容）❌ 不直接修改学生正文；只维护"记录 + 待办 + 状态 + 统计"。

#### 4.3.1 输入

- **记录上报**（3/4 主动调用）：辅导会话、检测批次、问题状态变化（如 4 的 issue 状态流转也可由 4 上报）。
- **导师反馈**：批注/评语/评审结论（M5 动作，由导师录入后经 7 记录；⚠ 批注来源见待确认问题）。
- **学生动作**：落实修改、异议（经 7 更新待办状态）。

#### 4.3.2 接口清单（MCP 工具 / CLI 子命令）

| 接口 | 调用方 | 说明 |
|---|---|---|
| `track.record_session(coach_report)` | 3 | 记录一次辅导会话（session、输入摘要、报告摘要、guardrail 是否拦截） |
| `track.record_check(check_report)` | 4 | 记录一次检测批次（run、issues 清单、评分） |
| `track.record_issue_transition(issueId, from, to, reason?, actor)` | 4 | 问题状态流转（accepted/fixed/appealed/closed/reopened） |
| `track.record_feedback(feedback)` | 导师侧 | 记录批注/评语/评审结论（M5 动作） |
| `track.update_todo(todoId, status, reply?, actor)` | 学生/导师 | 更新待办状态（待处理/已修改/有异议/已关闭/待复核） |
| `track.query_board(projectId)` | 学生/导师 | 返回 `TrackingBoard`（待办、统计、下一步动作） |
| `track.query_events(projectId, afterHash?, limit)` | 所有人 | 时间轴回放（按哈希链游标） |
| `track.verify_chain(projectId)` | 审计 | 校验哈希链完整性，返回首个断点 |

所有 record.* 返回 `{ "eventId": "uuid", "accepted": true, "chainHead": "sha256", "reportId": "..." }`。

#### 4.3.3 输出 `TrackingBoard`

```json
{
  "schemaVersion": "feedback.board.v1",
  "updatedAt": "2026-11-16T08:00:00Z",
  "todos": [{
    "todoId": "uuid",
    "source": "annotation|checkIssue|review",
    "sourceId": "uuid",
    "title": "补充对照组实验",
    "priority": "P0|P1|P2",
    "required": true,
    "status": "待处理|已修改|待复核|已关闭|有异议",
    "dueAt": "2026-11-20",
    "studentReply": null
  }],
  "stats": { "total": 12, "required": 3, "pending": 5, "disagreed": 1,
             "requiredCleared": false, "rate": 0.58 },
  "nextActions": ["处理 3 条必改批注", "回复 1 条学生异议"]
}
```

#### 4.3.4 状态机（对齐 9.5 / AC-06 / AC-09）

```
待处理 ──学生修改──> 已修改 ──导师复核──> 已关闭（通过）
   ▲                     │
   └──── 导师退回 ────────┘
待处理 ──学生异议(须理由)──> 有异议 ──导师处理──> 待处理(退回) / 已关闭(采纳)
必改项未清零 → 导师端「未清零」（BR-08）
```

## 5. 交互时序（接口视角）

### 5.1 单模块辅导闭环（图 4-2）
```
学生 ──进入模块──> [3] 辅导
   [3] ──inspect.query_latest──> [4]      （取当前评价）
   [3] ──生成六段式+骨架+追问+linkedIssues
   [3] ──track.record_session──> [7]      （记录辅导）
学生写作 ──初稿──> [4] 检测
   [4] ──生成 CheckReport（issues P0/P1/P2）
   [4] ──track.record_check──> [7]        （记录检测）
学生改 ──> [4] 复检（增量）──> track.record_issue_transition(→closed) ──> [7]
导师批注/评语 ──> track.record_feedback ──> [7]（生成待办）
学生落实 ──> track.update_todo(→已修改) ──> [7]
导师复核 ──> track.update_todo(→已关闭/退回) ──> [7]
ModuleState：未开始→进行中→(P0未清)待修复→(清零+导师确认)通过（BR-03）
```

### 5.2 导师评语闭环（AC-09）
```
导师写评语(必改2条) → [7] 生成必改待办
→ 学生处理 → [7] 待处理→已修改
→ 导师端「待复核」→ 导师复核通过 → [7] 已关闭，可 query_events 回放
```

## 6. 模块间数据流规则

| 规则 | 说明 |
|---|---|
| 单向依赖 | 3 → 4（只读评价查询）；3/4 → 7（只写记录）；**4 不读 3，7 不读 3/4 的成果**（避免环） |
| 版本绑定 | 4 的检测结果绑定 `docVersion`；旧版本问题清单保留，复检针对新版本 |
| 增量优先 | 段落修改 → 仅该段落检测（C-02） |
| 写入唯一 | 留痕/待办只允许 7 写入；3/4 不得写 `evidence/`、`advisor/` |
| 只读共享 | 模块之间不修改对方目录中的文件 |
| 幂等 | 同一请求按 `requestSha256` 返回同一结果（7 对 `eventId` 去重） |
| 失败降级 | 外部依赖（文献核验等）不可用标 `INCOMPLETE`，不得静默通过 |

## 7. 留痕事件契约（M9，7 唯一写入）

`evidence/events.jsonl`，只增不改，每条为 `EvidenceEvent`：

```json
{
  "eventId": "uuid",
  "projectId": "proj-001",
  "type": "coach.session.created | coach.report.created | check.run.created | check.issue.transitioned | check.run.completed | feedback.annotation.created | feedback.comment.created | feedback.todo.status_changed | feedback.review.passed | module.state.changed | guardrail.blocked",
```

## 8. 与 Codar 插件体系对齐

### 8.1 Skill 拆分（建议）

- 首期建议：三个 Skill 独立发布（standalone），后续打包一个 Plugin（`paper-writing-coach`）。

### 8.2 scripts CLI 契约
```
python scripts/coach.py --request coach/sessions/<sid>/request.json \
                        --out coach/sessions/<sid>/report.json
python scripts/inspect.py --request coach/checks/<rid>/request.json \
                          --out coach/checks/<rid>/report.json --rules rules/

python scripts/track.py board          --project <pid>
python scripts/track.py verify         --project <pid>
```
- 退出码：0 成功；2 请求非法；3 规则错误；4 外部依赖不可用（INCOMPLETE）。
- 全部输出 UTF-8 JSON，附 `requestSha256` 便于幂等。

## 9. 错误码

| 码 | 含义 | 处理 |
|---|---|---|
| `ERR_INVALID_REQUEST` | 请求字段非法/缺 context | 返回 `{error}`，不中断流程 |
| `ERR_MODULE_MISMATCH` | module_id 不在模块清单 | 同上 |
| `ERR_GUARDRAIL_BLOCKED` | 护栏拦截（如超60字成稿） | 输出降级版并标注 |
| `ERR_EXTERNAL_INCOMPLETE` | 外部核验不可用 | 标 `INCOMPLETE`，禁止过检 |
| `ERR_STALE_VERSION` | 对旧 doc_version 复检 | 拒绝并提示刷新 |
| `ERR_CHAIN_BROKEN` | 哈希链校验失败 | 报警并定位断点事件 |
