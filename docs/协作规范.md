# 协作规范

> **文档编号：DOC-004** · 状态：生效
> 主题：目录布局、个人空间规则、分支管理、PR 与提交约定。团队总览见 `README.md`，决策见 `docs/决策记录.md`。

```
└── temp/             临时文件（不入库）
```

## 2. 个人空间规则

- 每人使用 `members/<代号>/` 作为**独立开发空间和文档存放位置**：
  - `notes/`：个人文档、设计草稿、决策候选、学习笔记
  - `sandbox/`：个人试验代码
- 个人空间**入库**（便于备份与互相参考）、**非交付物**、**不参与打包**。
- 公共模块**不得 import/依赖**个人空间内容。
- 个人空间冲突概率为零；公共区冲突靠 CODEOWNERS 与评审解决。

## 3. 公共区域规则

- `contracts/`：契约唯一事实源；**改动单独 PR + 2 人评审**；schema 只加字段不改名，版本前缀。
- `docs/决策记录.md`：只追加；`docs/347模块接口与交互规范`：接口变更时更新；`docs/平台调研`：平台事实变化时更新；`docs/交接说明.md`：只做导航。
- 临时文件一律 `temp/`。

## 4. 分支管理（推荐：个人常驻分支 + 频繁 PR）

1. **main**（受保护）：永远可构建、契约测试全绿；只通过 PR 合并；至少 1 人 review（`contracts/`、`docs/决策记录.md` 等契约类改动 2 人）。
2. **dev/<代号>**（如 `dev/a`）：每人一条常驻个人分支，从 main 切出；日常提交在此；**每天**把 main 合进来（`git fetch origin && git merge origin/main`），避免大冲突。
3. **feat/<模块>-<主题>**（可选）：较大特性从个人分支切出，完成后 PR 到 main。
4. 禁止：直接 push main；在 main 上本地开发；契约与功能混在同一 PR。
5. 冲突处理：公共文件冲突当天解决；`contracts/` 冲突以契约评审结论为准；`members/` 永不冲突。
6. 发布：12 月底 `v0.1-prototype` tag → 1 月 `v0.2` → 2 月 `v1.0`。

## 5. PR 检查清单

- [ ] 只动一个主题（契约 / 功能 / 文档 / 个人空间）
- [ ] 提交信息符合约定式（见下）
- [ ] 契约测试通过（对桩或真实现）
- [ ] 涉及契约：已更新 fixtures 与契约测试
- [ ] 不包含 `temp/` 与敏感数据

## 6. 提交约定

- 格式：`type(scope): subject`，如 `feat(inspector): add anchor parser`、`docs(adr): record split decision`、`test(contracts): add inspect summary fixtures`
- 小步提交；契约变更提交单独成条。
