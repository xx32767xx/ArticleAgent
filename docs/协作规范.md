# 协作规范

> **文档编号：DOC-004** · 状态：生效
> 主题：目录布局、个人空间规则、分支管理、PR 与提交约定。团队总览见 `README.md`，决策见 `docs/决策记录.md`。

## 1. 目录布局

```
├── contracts/        公共·契约包（Schema+fixtures+契约测试）  甲、乙

└── temp/             临时文件（不入库）
```

## 2. 个人空间规则

- 每人使用 `members/<代号>/` 作为**独立开发空间和文档存放位置**：
  - `notes/`：个人文档、设计草稿、决策候选、学习笔记
  - `sandbox/`：个人试验代码
- 个人空间**入库**（便于备份与互相参考）、**非交付物**、**不参与打包**。
- 公共模块**不得 import/依赖**个人空间内容。
- 个人空间冲突概率为零；公共区冲突靠 CODEOWNERS 与评审解决。

## 3. 公共区域规则

- `contracts/`：契约唯一事实源；**改动单独 PR + 2 人评审**；schema 只加字段不改名，版本前缀。
- `docs/决策记录.md`：只追加；`docs/347模块接口与交互规范`：接口变更时更新；`docs/平台调研`：平台事实变化时更新；`docs/交接说明.md`：只做导航。
- 临时文件一律 `temp/`。

## 4. 分支管理（轻量：按区域区分审查强度）

1. **main**（受保护）：永远可构建、契约测试全绿；**只通过 PR 合并**（不直接 push）。
2. **dev/<代号>**（如 `dev/a`）：每人一条常驻个人分支，从 main 切出；日常提交在此；每天把 main 合进来。
3. **个人工作区（`members/<代号>/`）改动**：随时开 PR 合 main，**免评审**，作者自行 squash 合并，可频繁操作。
4. **公共区域（`contracts/`、`docs/`、`skills/`、`rulepacks/`、`servers/`、`tools/`）改动**：必须走 PR，**1 人评审**（任意非作者）；`contracts/` 与 DOC-002 决策条目需**搭档确认**（对方模块负责人，不必 2 人）。
5. **信任前提**：每人只写自己的 `members/<代号>/` 与自己 owner 的公共目录；**跨区域改动先和 owner 打招呼**。
6. 冲突处理：`members/` 永不冲突；公共文件冲突作者解决，复杂时拉 owner 协助，当天解决。
7. 发布：12 月底 `v0.1-prototype` tag → 1 月 `v0.2` → 2 月 `v1.0`。

## 4.1 PR 归属、评审与合并（轻量）

- **谁创建**：发起改动的人自己开 PR；个人工作区建议先开 Draft 只是习惯，不强制。
- **个人工作区**：**免评审**——PR 作者自行合并；只需自查"不夹带公共区文件、不含敏感数据"。
- **公共区域**：**1 人评审**（任意非作者，CODEOWNERS 指定的优先）；`contracts/` 与 DOC-002 决策条目需**搭档确认**。
- **合并**：approve + CI 绿后作者本人 **Squash merge**；个人工作区无需等待 approve。
- **信任前提**：遵守 §4 第 5 条的区域分配；越界改动先报备。
- **冲突**：作者解决；公共文件复杂冲突拉 owner 协助，当天解决。

## 5. PR 检查清单

- [ ] 只动一个主题（契约 / 功能 / 文档 / 个人空间）
- [ ] 提交信息符合约定式（见下）
- [ ] 契约测试通过（对桩或真实现）
- [ ] 涉及契约：已更新 fixtures 与契约测试
- [ ] 不包含 `temp/` 与敏感数据

## 6. 提交约定

- 格式：`type(scope): subject`，如 `feat(inspector): add anchor parser`、`docs(adr): record split decision`、`test(contracts): add inspect summary fixtures`
- 小步提交；契约变更提交单独成条。
