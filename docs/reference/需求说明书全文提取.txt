[Heading1] 1. 引言
[Heading2] 1.1 编写目的
[] 本文档面向产品经理、研发工程师、算法工程师、UI/UX 设计师、测试工程师、教学管理者与院校合作方，完整描述"科技论文智能辅导平台"的产品定位、总体框架、功能模块、AI 辅导规格、模板与格式引擎、非功能要求、验收标准与实施路线，作为后续原型设计、技术方案、开发排期与验收测试的唯一需求基线。
[Heading2] 1.2 一句话产品定义
[] 一个把"科技论文写作课"的讲授—练习—批改—反馈过程搬进浏览器的论文教练平台：按论文模块逐段推进，边讲边写、边写边查、边查边改；它教你怎么写、检查你写得对不对，但不替你写。
[Heading2] 1.3 现状痛点
[] 编号
[] 痛点
[] 表现
[] 后果
[] P-1
[] 学生零基础
[] 不知道"摘要"是什么、写多少字、含哪几要素，不清楚正文与结论的分工
[] 反复重写，挫败感强，延期毕业
[] P-2
[] 格式返工
[] 页边距、标题层级、图表编号、参考文献样式反复出错
[] 据团队调研，导师批注中约 40% 与格式相关；学生 30%—50% 时间耗在排版
[] P-3
[] 导师一对多
[] 一位导师带 5—20 名学生，无法逐句辅导
[] 批注重复、反馈滞后、质量不均
[] P-4
[] 通用 AI 直接代写
[] 大模型一键生成全文
[] 学生没学到、AIGC 率超标、答辩露怯，触碰学术不端红线
[] P-5
[] 检测滞后
[] 查重、AIGC 检测在提交前才做
[] 发现问题时来不及修改，只能推倒重来
[] P-6
[] 过程不可见
[] 无法判断论文是谁写的、改了多少
[] 过程性评价缺乏依据，学术诚信无证据链
[] P-7
[] 院校规范差异大
[] 每所学校、每个期刊的模板与规范都不同
[] 通用工具无法覆盖，只能人工套模板
[Heading2] 1.4 产品定位与边界
[] 平台做四件事：
[] 1. 教——按科技论文写作课程的讲授顺序，对每个论文模块提供"是什么、为什么、怎么写、常见错误、范例对照"的讲解型辅导。
[] 2. 查——对学生写出的内容做检测型辅导，把问题定位到句、解释原因、给出改法、复检闭环。
[] 3. 导——导师在线指导与评语：行内批注、维度评分、评审轮次、书面意见，全部结构化留痕，可回放、可统计、可举证。
[] 4. 管——提供 Overleaf 式在线写作环境、学校/期刊模板自动生成、课程编排与过程性评价管理。
[] 平台明确不做：
[ListBullet] 不做"输入题目一键生成整篇论文"的生成器；
[ListBullet] 不输出可直接粘贴的整段成稿（详见 14.1「不代写护栏」）；
[ListBullet] 不代替导师给出成绩，只提供证据与建议。

[Heading2] 1.7 术语表
[] 术语
[] 含义
[] 模块（Module）
[] 论文的一个可独立撰写与辅导的单元，如"摘要"
[] 四件套
[] 每个模块固定的辅导组合：讲解 · 框架 · 检测 · 打磨
[] 讲解型辅导
[] 面向"不会写"的知识与示范输出，不评价学生文本
[] 检测型辅导
[] 面向"写错了"的问题诊断与修改建议
[] 模板 DSL
[] 描述学校/期刊排版规范的领域特定语言，可编译为 LaTeX 与 DOCX
[] 过程性证据链
[] 版本快照 + 输入轨迹 + 辅导对话 + 检测整改记录构成的原创性证据
[] 盲审版
[] 去除作者、导师、致谢、成果等身份信息的送审版本
[] 评语
[] 导师对模块或全文的结构化评价，含结论、维度评分与改进项
[] 评审轮次
[] 一次正式的导师评审活动（初审 / 二稿 / 预答辩 / 送审），绑定一个冻结版本
[] 留痕事件
[] 写作与指导过程中产生的、记录一次状态变化的最小事件单元

[Heading1] 4. 业务流程
[Heading2] 4.1 论文写作全流程与 AI 辅导触点
[] 图 4-1 说明：从上到下共四条轨道——学生动作（实线橙）、讲解型辅导（虚线绿）、检测型辅导（虚线金）、导师指导与评语（虚线蓝）。学生在 8 个阶段推进，每个阶段同步获得“讲解 + 检测”两类辅导；导师在立项、开题、设计、实验、撰写、送审等关键节点介入批注与评语；问题未清零可回到上一模块重写；四条轨道的全部行为写入底部留痕带。
[Heading2] 4.2 单模块辅导闭环

[] 6
[] 研究方法与模型设计
[] 技术路线、方法选择理由、模型假设与符号、算法流程
[] 假设未说明、符号未定义或重复定义、方法与研究问题不匹配、缺可复现信息（参数/数据/工具版本）

[] 7

[] 结论逐条对应研究问题
[] 9

[] 每条创新点有对应章节与证据

[] 双向匹配、全部可验证

[] 致谢
[] 写法与边界，避免敏感信息

[] 无敏感信息

[Heading2] 9.4 业务规则
[ListBullet] 批注与检测问题分属两条线：批注来自人，问题来自系统，同一条文本上两者可并存，界面用不同颜色区分，可相互引用（BR-10）。

[ListBullet] 批注侧栏与编辑器同屏，支持“批注清单”视图批量处理与拖拽定位。

[] 1. 导师 30 分钟内完成 10 名学生的阶段性批注（借助问题清单、评语模板与批量批注）。
[] 2. 每条评语可追溯到人、时间、位置，并可导出为学生可见的《指导意见清单》。
[] 3. 学生处理完所有“必改”批注后，导师端状态自动同步为“待复核”。
[] 4. 导师一学期后能答出“我给这个学生提了多少条必改意见、他改了多少”，且数据可导出。

[Heading2] 14.5 技术架构要求
[ListBullet] 多智能体编排：编排器 + 讲解 Agent + 检测 Agent 群（结构专家、语言专家、规范专家、数据一致性专家、合规专家）。

[ListBullet] 评测闭环：所有申诉与采纳行为回流为评测样本，每月更新评测集并发布模型与规则版本。

[Heading1] 19. 风险与对策
[] 编号
[] 风险
[] 影响
[] 对策
[] R-01
[] AI 变相代写，学生仍不学
[] 学术不端、产品价值丧失
[] 不代写护栏（14.1）+ 生成占比报告 + 强化口试/答辩环节 + 教师抽查辅导记录
[] R-02
[] 学校模板差异极大且经常变更
[] 模板维护成本高、格式不准
[] 模板 DSL 抽象 + 学校共建 + 自动抽取官方 Word 模板 + 双人校验发布
[] R-03
[] 检测误报引发信任危机
[] 学生抵触、教师质疑
[] 每条问题可解释可申诉 + 提供依据链接 + 分级呈现 + 误报率纳入模型发布门禁
[] R-04
[] AIGC 检测本身不可靠
[] 误伤学生、纠纷
[] 明示局限、仅作参考、多信号综合判断、不单独作为处分依据
[] R-05
[] 引用核验依赖外部库，覆盖不全
[] 中文文献核验率低
[] 多源核验 + 标注"无法核验"而非"虚假"，保留人工复核入口
[] R-06
[] 大模型成本高
[] 毛利压力
[] 增量检测、缓存复用、分层路由、私有化小模型承担基础规则类任务
[] R-07
[] 数据安全与隐私
[] 论文泄露风险
[] 私有化部署选项、加密存储、最小权限、审计留痕、不用于训练
[] R-08
[] 与通用 AI 工具竞争
[] 用户流失
[] 差异化定位：课程映射 + 模板 + 导师协同 + 过程证据，而非“更强的生成”
[] R-09
[] 导师不愿用平台（怕麻烦）
[] 评语落不了地，M5 空转
[] 评语模板 + 语音批注 + 共性问题面板 + 与现有 Excel / 纸质流程对齐 + 工作量可折算
[] R-10
[] 全程留痕引发隐私顾虑
[] 学生抵触、院校合规风险
[] 告知同意 + 最小必要 + 明细脱敏 + 明确不作自动处置 + 可审计的访问日志
