## 1. 项目与角色

- **项目**：科技论文智能辅导平台（需求说明书 V1.1，SRS/PRD）中的 **347 部分**，以 **Codar（科搭，SpeedAI 出品）插件**形态开发交付。
- **3 / 4 / 7 是什么**（来自 `结构总览.png` 功能规划表）：
  - **3 论文辅导智能体**（18–28 人周）：讲解型辅导——讲解、骨架、追问、范例、自检清单。**只教写法，不产出成稿**（红线：连续正文 ≤60 字）。
  - **4 论文检测智能体**（20–32 人周）：检测型辅导——规则检测、问题清单（句级锚点/严重度/依据/修改建议）、评分、复检。
  - **7 导师反馈落实追踪**（MVP 4–5 / 完整 10–13 人周）：把导师批注/评语与检测问题聚合为待办，维护「待处理→已修改→待复核→已关闭」状态机，并做过程记录。
- **对应需求章节**：M4（8 章、14 章）、M5（9 章）、M9（13 章）；验收场景 AC-02 / AC-06 / AC-09。

## 2. 已确定的决策（评审通过的）

1. **职责隔离 + 接口化调用**：
   - 3 只负责"指导"，**辅导时通过接口调用 4** 获取当前论文评价结果（`inspect.query_latest`），据此调整讲解侧重；
   - 4 只负责"评价"，不指导、不代写；
   - 3/4 每次运行都**调用 7 的接口**上报过程记录；**7 是过程记录的唯一写入方**（哈希链事件流 + 待办状态机 + 复核统计）。
2. **接口规范**：`docs/347模块接口与交互规范-v0.2.md`（统一 Context、三类请求/响应契约、状态机、事件契约、错误码）。
3. **仓库策略**：单仓库（monorepo），契约包 + 模块目录；桩（stub）先行 + 契约测试；两层 CI（每次提交跑对桩契约测试；合并前/夜间跑真实现集成测试）。
4. **交付形态**：先做三个独立 Skill（`paper-coach` / `paper-inspector` / `advisor-tracker`），后续可打包成一个 Plugin；发布需管理员（SpeedSkills 暂未对第三方开放自助发布）。

## 4. 平台关键事实（Codar）

- 插件单元 = **Plugin**（可版本化能力包），内含 **Skill**（含 `SKILL.md` 的目录）与 **MCP**（`.mcp.json`）；市场 = SpeedSkills（skill.speedai.com）。
- 包格式：`.codex-plugin/plugin.json` + `skills/<name>/SKILL.md`（+ `scripts/` `references/` `assets/` `agents/openai.yaml`）。
- 本地安装：`~/.codar/plugins/releases/<pluginId>/<version>/`；账本 `~/.codar/desktop/installed-*.json`；桌面端「导入本地 Skill」选**含 SKILL.md 的目录**即可。
- 发布：压缩包交管理员 → 管理后台「发布」→ 自动识别 → 审核上架；自助发布未开放。
- v4 契约文档：`docs/reference/v4-api-contract.md`、`docs/reference/v4-data-models.md`。
